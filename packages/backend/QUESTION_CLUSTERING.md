# 代表问法聚类

ChromaDB 单集合、多集合（含增量 UMAP）以及文本投影默认在 UMAP 前进行聚类。文件已有向量时，同时指定 `--vector` 和 `--text`；Python 接口使用 `compute_vector_projection(..., text="问题列名")`。

结果新增 `representative_question`，在散点图上色字段中选择它即可。同名原始列会保留，新列自动加数字后缀。未达到相似度阈值的记录为 null，使用前端已有的空值颜色。所有原始行仍参与 UMAP，聚类只添加标签，不减少投影点。

算法规则：

1. ChromaDB 单次读取文档、元数据、向量，并按 ID 排序；文件保持输入行顺序。单响应避免分页期间和文本/向量分开读取导致的错配；数据库级事务快照保证取决于 ChromaDB 服务端。
2. 向量转换为 float32 并 L2 归一化；文本精确去重，不裁剪空格，保留请求次数，同文本使用首次出现的向量。
3. 按频次降序、首次出现顺序打破平局，以 0.97 相似度贪心合并尚未分配的问法；不做传递闭包。
4. 合并组保留原始精确问法数及请求数。候选代表按 cosine ≥0.73 覆盖合并组，每轮选择新增覆盖得分最高者：`0.4 × 新增精确问法数/全部精确问法数 + 0.6 × 新增请求数/全部请求数`。平局按原始顺序选择；同时达到 80% 和 90.1% 才停止。
5. 回到每个精确问法，寻找最近的已选代表，重新用 0.73 判定覆盖并展开回原始行。日志分别输出合并阶段和最终精确覆盖率。后者可能低于目标，此时记录警告，不以合并阶段的覆盖率冒充最终覆盖率。

缺失的非文本值不参与代表选择，计入未覆盖请求；零向量和非有限值会明确报错。聚类结果使用独立磁盘缓存：缓存键包含按输入顺序排列的全部文本、归一化前的 float32 向量及其形状、全部聚类参数和算法缓存版本。完全一致时直接恢复标签、代表问法和两阶段覆盖率；任一项改变则重新计算。重启后端或集合被内存缓存淘汰后也可命中磁盘缓存，但仍需要读取文本和向量来计算缓存键。投影缓存包含向量内容，现有 ID 对应向量被修改时不会复用旧投影。纯文本投影缓存同时保存聚类列，聚类参数变化使该缓存失效。

聚类缓存与 UMAP 缓存一起存放在应用缓存的 `projections` 目录，文件名为 `question-clusters-<SHA256>.json`。删除该目录可同时清理两者；只删除 `question-clusters-*.json` 可单独清理聚类缓存。写入采用临时文件和原子替换，缓存损坏会自动重算，缓存读写失败不阻止返回聚类结果。

参数通过 `packages/backend/.env.example` 中的 `QUESTION_CLUSTER_*` 环境变量配置；修改后重启后端以重新加载集合。默认保留原参数，尚未用当前 Qwen 模型的标注问法校准。提高 `SIMILARITY_THRESHOLD` 会收紧归类条件；调整后应结合最终覆盖率与人工核查代表问法判断效果。

计算不保存 N×N 相似度矩阵，额外工作内存为 O(ND + N)，但精确相似度计算仍有二次时间成本，大集合加载会增加耗时。

在仓库根目录运行验证：

```powershell
.venv/Scripts/python.exe -m unittest discover -s packages/backend/tests -v
```
